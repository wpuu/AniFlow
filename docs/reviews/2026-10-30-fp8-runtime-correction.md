# FP8完整成片窗口纠正（预算方法变更待用户确认）

## 先纠正不可行的15分钟窗口

用户已批准在GPU停止时准备两份Comfy-Org FP8 scaled扩散权重，保持800×1376、121模型帧、24fps、20步及既定5秒输出。本轮没有再次开机或提交视频。

准备阶段进一步核对了实际权重头和固定版本源码，发现此前15分钟窗口没有充分做计算量核查，不能作为合理完整成片计划。不能先开机再用这个窗口掐断任务。

已核前提：VAE时空stride=(4,8,8)，Transformer patch=(1,2,2)，40层、5120维、40个head；实际权重头相符。121帧的潜在时间长度为31，空间patch网格为50×86，序列长度133300。固定实现对完整q/k/v做全局注意力，未启用窗口或稀疏近似；CFG3.5保留正负条件。

标准稠密self-attention的QK及AV计算量估算为4×N²×D×layers，即每次forward约14.556 PFLOP。L4公布的FP16 Tensor Core指标含稀疏时不能直接用于该稠密计算；按约121TFLOP/s稠密理论上限，单forward的注意力部分约需120秒。20步即使仅单forward也约40分钟；CFG的两条件约80分钟。该估计不包含模型装载、线性层、数据搬运、VAE解码和编码，是计算量下界分析，不是完成耗时实测。

本FP8文件scaled_fp8张量为F8_E4M3、shape=[0]；固定Comfy版本可走量化线性层的原生混合精度，不必添加可能损害质量的--fast开关。但权重量化不会自动把注意力QK/AV也改为FP8，不能据FP8峰值算力宣称15分钟能完成。

依据：[固定Wan注意力实现](https://github.com/Comfy-Org/ComfyUI/blob/63be2f9b82ad0dac88a7ceaa28a9cf3154125a18/comfy/ldm/wan/model.py)、[CFG实现](https://github.com/Comfy-Org/ComfyUI/blob/63be2f9b82ad0dac88a7ceaa28a9cf3154125a18/comfy/samplers.py)、[Wan原始A14B配置](https://github.com/Wan-Video/Wan2.2/blob/main/wan/configs/wan_i2v_A14B.py)、[NVIDIA L4规格](https://www.nvidia.com/en-us/data-center/l4/)。实际权重头读取来自已校验范围分块，最终模型仍必须全文件SHA通过。
