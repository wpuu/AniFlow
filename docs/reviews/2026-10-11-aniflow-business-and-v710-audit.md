# AniFlow｜独立商业可行性与上游 v7.1.0 适配审计

> 日期：2026-10-11（中国时间）。实际记录模型：GPT-6，未声称切换其他模型或思考档。  
> 仓库基线：`main@4a09aa3d93f25f753c3379fd8bf4501427a266a0`（2026-09-29）。  
> 上游核验：`lcy362/agnes-video-generator@v7.1.0`（2026-10-09 发布）。  
> 状态：**代码静态核对、最新公开信息核对完成；未执行 Windows 实机验证、真实 API/Key 调用或视频生成。**  
> 存储策略：先在审计隔离分支保存，不自动合并、部署或修改用户凭证。

## 1. 独立结论

**有限继续（GO / validate），保留仓库，不新建重复的视频生成系统，也不直接排产 30 集。** 将 AniFlow 收敛为有证据的科普脚本、原创毛毡角色“雪所长”、镜头与角色锁定、最终事实核验和人工 QA 层；成熟开源引擎负责队列、生成、配音字幕和拼接。现有项目确实有工程资产，但**视频全链路尚无最近实机成片证据，首笔收入与复购也未验证**。

最值得检验的两个问题：① 每条合格视频的真实人工时间及失败率是多少；② 是否有客户愿意购买范围清楚的交付，而不只说喜欢视频或免费 API。把“作者账号广告曝光”与“给客户制作短视频”作为不同商业模式分别验证。

## 3. 新旧引擎之间已经证明的兼容性断点

直接对照 `scripts/InstallVideoStudio.ps1` 与上游 v7.1.0 的 `core/api/agnes_video.py`：

1. 旧安装器要求查找 `queue_retries = 0` 及旧版 `delay = _QUEUE_RETRY_BASE_DELAY + random.uniform(...)`。**这两个完整锚点在 v7.1.0 的相应提交函数里都不存在。** 只改版本号就套旧补丁属于错误升级。
2. v7.1.0 用 `core/api/retry_policy.py` 统一将 429、所有 503、`video_queue_full` 等放入繁忙重试轨：首跳不叠加手工等待，后续固定间隔加次数上限。普通故障有独立退避轨；参数 `AGNES_VIDEO_BUSY_RETRY_ATTEMPTS` 替代 `AGNES_VIDEO_QUEUE_RETRY_SECONDS`。
3. 429 分支仍有 `ring.rotate()`；503 忙轨下一轮提交由 `ring.next()` 正常选 Key。因此**不能直接沿用旧笔记的“9 Key 轮询需 4.5–9 分钟”结论**，也不应不测就再次插入立即强制旋转补丁。
4. 401 错误登记显示 Key 的认证失败次数，但代码明确不自动从池中移除 Key。上游新版已提供错峰队列提示、裸 503 重试与上传恢复处理。
5. 上游文档明确：`agnes-video-2.5-flash` 在 **9:16 竖屏可能有旋转异常**，提供可选 `AGNES_FIX_V25_PORTRAIT_ROTATION=1`。必须把视频文件的画面方向、宽高、裁切及播放器效果纳入实机验收。不能把历史曾报 `fail_to_fetch_task` 的 `agnes-video-v2.0` 当可靠备用。

**决策：旧补丁标记为历史版本专用；首先离线验证原生 v7.1.0。**

## 4. 能力边界与生产方案

- 官方 `agnes-video-2.5-flash` 文档列出单片 4–12 秒、720P、`keyframe` 首/尾帧模式及 `reference` 参考图模式；两种模式的图片字段互斥。尝试连续动作镜头用首尾帧衔接，跨场景/跨集用标准角色定妆参考，两者都必须对比真实合格率。
- 免费报价目前是**限时免费**，不能作为永久免费承诺。多 Key 合规调度不代表队列独立或吞吐线性提升。
- `src/aniflow/factpack.py`、`src/aniflow/shotlist.py` 已有事实包与镜头表能力；`src/aniflow/pipeline/final_qa.py` **也已存在自动画质检查**，但目前主要针对旧 A→B→C 的 10 秒无声短片、采样中间接缝，**尚不能宣称覆盖最新约 46 秒、8 镜头、配音字幕**。
- 优先比较两条成片方法：A：八个镜头都生成动态视频；B：约 2–3 个核心动态镜头、其余角色静帧/科学图解/运镜，再统一配音字幕。记录总尝试数、队列时间、人工挑片、角色一致率和最终质量。优先减少不可控返工。
- 事实核验不应只停留在“输给引擎之前”：引擎可能拆句、改写或翻译旁白，**最终音轨和字幕需要再次与事实包对照**。生成的猫喝水物理动态不能未经核查就当科学事实。

## 5. 合规、授权与发布

- 2025-09-01 《人工智能生成合成内容标识办法》实施。不同义务对应生成平台、传播平台及上传者；个人发布应正确声明、保留标识。
- 2026-05-12 中央网信办要求短视频平台提供六类“必选标签”，包括“含有AI生成内容”“含有营销信息”，并将选择标签列为发布必经步骤。运营时以目标平台当前实际流程核验，不应只写一个文件 metadata 文本就宣称已完全满足隐式标识规范。
- 旧方案给出的文字尺寸、时长技术指标须与现行标准原文及适用主体交叉核对；不能仅从历史笔记硬编码。
- 未核实 `edge_tts` 非官方接入方法的商业授权，不能凭免费就视为可商用。真正接客户视频前明确 TTS、素材、音乐及字体授权。
- CapCut 2026-04-15 **美国用户条款**限制自动脚本交互；不能以此直接推定国内剪映条款完全相同，但不能把无授权自动控制浏览器当作稳定核心交付环节。
- GitHub 仓库公开，禁止写入真实 API Key、Cookie、R2 密钥、用户原始资料。两套本地应用默认可能都占用 `8765`，要隔离端口。Docker 升级必须保留 `/app/.working_dir` 和 `/app/.agnes_config` 的持久化数据。

## 6. 盈利重审：以限定交付先证明有人付费

不接受“至少 30 集后才可能接品牌单”为硬规则，因为缺少价格、购买、曝光数据。区分：

- 自营账号：关注真实观看、完播、记住角色等；广告、分成、周边属增量，不能提前计算保底现金流。
- 付费视频制作：尽早尝试小单，限定**一个角色、一条短片、固定镜头、一次修改**，实测制作成本、交付与付款。不要向写实人物岗位展示毛毡猫样片并宣称具备写实人物能力。

2026-10-10 的 Upwork 只读抽样存在短视频角色定妆/5–10 秒付费试片需求，以及人物视频制作与工作流培训需求，**仅证明买方公开提出需求，不证明这条赛道已适合我们的特定作品或取得真实订单**。

旧估算每集 3.5–5.5 小时人工；若不验证就排产 30 集，可能需 105–165 小时。建议先做 3 条试片，提议总主动人工不超过 12 小时、新增现金不超过人民币 300 元；这是风险控制建议，非已发生费用或支出批准。

## 7. 下一阶段严格验收门

| 阶段 | 应完成的操作 | 真实完成标准 | 不得代替 |
|---|---|---|---|
| P0-A | 隔离版本化验收原生 v7.1.0；旧脚本/配置差异与备份，静态测试 | 有版本、测试与差异证据，旧补丁没有硬套到新版 | 不以修改版本号充当兼容验收 |
| P0-B | 一个 Key、一个最小 9:16 镜头的真实测试 | 视频文件、HTTP及失败原因、video_id、方向/尺寸、时长、等待时间 | 任务提交成功不等于生成成片 |
| P0-C | 比较 `keyframe`、`reference` 角色和动作稳定 | 相同素材的对比、不同镜头的合格率及失败留样 | 不能靠少量请求证明服务器队列按账号隔离 |
| P0-D | MYCL-001 第一条 30–46 秒混合制作品 | 片段、旁白文字复核、字幕、许可、合规声明、终审结果全部落盘 | 自动 QA 评分不等于人工终审 |
| P1 | 另外两条样片 + 小规模购买验证 | 主动人工时、重抽、成本、询单/付款证据 | 未完成不能进入排产 |
| P2 | 确实发现可重复耗时瓶颈才研发服务化 | 功能确实降低工时或提升转化 | 不按写代码量考核 |

无需 Key 现在就能做：静态审计、隔离分支、测试用例、打包脚本安全兼容修复、简化验收记录。实机验证、真正成片、发布或产生第三方收费，需要真实用户环境与有效授权，不能伪造通过。
