# AniFlow P0-036｜视频提交结果未知时的防重复保护

审计日期：2026-10-25。隔离分支 audit/2026-10-25-claude-grok-ui。
用途：完善已选 Grok 工作台对本机 H3 模拟服务的任务恢复，而不是启用 AWS。

## 已发现的问题

之前 Mock UI 只用页面内的 submitting.current 阻止同时点击。如果服务器已经受理 POST /jobs、但网络在返回 202 前中断，界面会显示失败；用户刷新并再次点击，会创建新的幂等键和任务。真实 H3 GPU 情况下可能额外消耗赠金。此问题不在 ZIP 原始设计中得到解决。

## 本轮改动

- 本机 SQLite Mock Bridge 新增只读 GET /api/studio/mock/requests/{idempotency_key}，按首次提交时的唯一编号查找服务端已接收的任务，不创建新任务。404不是确认未提交，客户端不得因此自动重发。
- 前端成功上传首帧后、发起可能耗费GPU的创建POST前，先把随机幂等键与创建时间持久保存在浏览器本地；**不保存图片Base64、提示词、API密钥或AWS凭证**。
- 创建结果明确成功时，删除本地保护，按原服务器任务ID加入 SQLite 历史。收到明确4xx拒绝时可解除保护；网络超时、HTTP 5xx、无法解析响应等结果不明确时保留保护。
- 保护期间生成按钮禁用；用户可点击“查询原任务”（只读，不再POST）。刷新浏览器会尝试一次自动只读恢复；仍查不到则保留未知状态。只有用户读懂风险并明确确认，才能放弃本地保护；这不取消任何已经受理的远程任务。
- Chrome E2E（本地模拟、零AWS）须证明：创建POST已在服务器落库但浏览器收不到响应，重启页面与查询失败不导致重复创建；恢复GET成功后仅原任务存在。
- 后端测试须覆盖首次查询404、POST受理、幂等键读回原任务、非法编号/输入拒绝。

## 上线边界

这只是**Mock-only** 自带任务可靠性验证。真实 H3 的 ComfyUI prompt_id、异步模型加载/故障恢复、下载哈希、EC2启动与停止、IAM预算、SSM隧道、模型合法性未实现。不可把蓝色假视频叫“生成成功”。

两份原始 ZIP、原先 PR #2 的 Windows 8765 视频前端和主分支 main 均不修改。PR #7 保持 Draft。首次 AWS 实例实际启动必须另行核验到期赠金、按需实例配额、许可和单次预算授权。
