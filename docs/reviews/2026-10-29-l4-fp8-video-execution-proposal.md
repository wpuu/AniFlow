# L4原输出规格5秒视频：FP8方案（待批准，未实施）

目标仍是一条可在Windows播放、通过完整解码和SHA校验的真实5秒猫咪视频。本文仅提出执行方案，不代表已下载量化模型、修改工作流、开机、生成视频或验证画质。当前实例保持Stopped。

两份合计28,589,485,664字节。保留原FP16文本编码器和VAE，减少同时改变的变量。原FP16权重、清单和既有原始ZIP不覆盖、不删除。

分辨率、帧数、帧率、步数及素材均保持原配置：800×1376、121模型帧、24fps、20步；最终交付774×1376、120帧、5秒、CRF18、无插帧或放大。使用已经批准的猫咪首帧与动作，不重复索取素材。

**保持这些输出规格不等于量化零画质损失。** 两份FP8权重约为原FP16文件的一半，有利于降低权重驻留压力；文件体积不等于实际显存峰值。L4支持FP8 Tensor Core，但当前加载器按文件元数据选择混合精度运算，并非全流程自动以原生FP8运算。

本次未找到同一L4、800×1376、121帧、20步的可信一手速度基准，也未找到FP8与FP16绝对等观感的官方保证。因此不能预先保证“几分钟成片”或“量化无损”。实际成片需检查猫咪外观、花纹、运动、背景稳定性及闪烁；没有MP4就不能报告效果验收完成。

## 2. GPU关闭时完成全部准备

1. 在G盘全新独立目录准备两份文件，逐份核固定来源、字节和完整SHA。当前G盘空闲约90.9GB，足以准备这两份文件；原有分片不覆盖。本文尚未开始下载。
2. 新增明确FP8配置、清单、工作流及门禁验证，保留原FP16配置。现有验证锁定FP16文件和加载方式，不能只改文件名或跳过校验。固定Comfy已内建scaled-FP8加载，不新增GGUF自定义节点。
3. 离线准备私有S3临时上传、机内复制与校验脚本、精确设备/磁盘预检、计时、监测、私有结果自动保存、Windows下载和新双停机保护。临时模型对象仅用于传输，复制校验后清理；G盘文件和原FP16保留。不得删除其他对象或实例。
4. 根盘实际余量尚未测得，不能假定180GB盘再放得下28.6GB。若走根盘缓存，需至少37,179,420,256字节空闲（新增两文件加8GiB安全余量）。否则评估G6规格自带本地NVMe；必须实际识别instance-store、排除根盘及已有数据、确认安全后使用，不能擅自格式化不明设备或扩盘。

GPU开机后仅做已准备好的复制、校验、加载和生成；不在线安装依赖或从Hugging Face临时摸索下载。复制或加载超过预设准备窗口、空间不足或任何校验失败即停止，不能吞掉整段运行预算。

## 3. 一次正式任务，不做重复小样

正式运行窗口草案为15分钟，独立应急窗口再10分钟；必须先重新实证主保护、独立备用和本次固定截止。机内截止也需绑定同一当前boot。实例仍只准一台，不提额、不升级。

只提交一次完整20步5秒任务，持久保存请求键和prompt ID。前两步就是这条正式任务的性能测量，不另提交短样片后重跑。根据实际已耗时间、相邻步间隔、剩余步数和模型切换/解码余量，计算能否在截止前完成；通过则原任务继续。无可靠余量时及时中止，不改步数/分辨率凑结果，不自动重试未知结果。

这是一轮受控实测，并非已证明15分钟内必出片的配置。如果量化后速度仍不足，当前机器与本轮费用边界仍不能满足成片目标，不能继续把短时试验作为成功方案。
