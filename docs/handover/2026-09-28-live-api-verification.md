## 2. 更正上一轮的一个错误判断

接管审计里我写了「`agnes-video-v2.0` 已下架」。**这个说法不准确，现更正：**

`GET /v1/models` 实测返回 **12 个模型**，`agnes-video-v2.0` **仍在列表里**：

```
agnes-2.0-flash          agnes-image-2.0-flash     agnes-video-2.5
agnes-2.5-flash          agnes-image-2.1-flash     agnes-video-2.5-flash
agnes-2.5-pro            agnes-image-2.5-flash     agnes-video-v2.0
agnes-2.5-pro-alpha      agnes-3.0-flash
agnes-2.5-pro-beta
```

准确描述应该是：**从官方文档索引和定价页移除，但 API 仍然列出它。**

不过实际调用它会返回 `fail_to_fetch_task` —— 所以它是**「列而不可用」**。
另外发现两个文档里没有的模型：`agnes-2.5-pro-alpha`、`agnes-2.0-flash`（文档称已弃用）。

> **原建议不变且被实测加强**：不要在 `agnes-video-v2.0` 上投入任何开发。
> 它没有文档、没有价格、调用直接失败。前端里那套 V2.0 参数契约应当删除。

## 3. 图片链路：完全跑通，质量超预期

**请求**：`agnes-image-2.5-flash` · `size: "1K"` · `ratio: "9:16"` · `extra_body.response_format: "url"`

| 指标 | 实测 |
|---|---|
| 耗时 | **9.3 秒** |
| 输出尺寸 | **736 × 1312** —— 与官方 9:16 / 1K 档位表**完全一致** |
| 文件大小 | 1,085 KB PNG |
| 返回形式 | 公网 URL（`platform-outputs.agnes-ai.space/images/t2i/...`） |
| 毛毡风格还原 | **优秀** |

出图内容：银虎斑美短、小白大褂、站在厨房台面、面对微波炉，
羊毛纤维质感、手工毡化痕迹、微缩实景布光都到位，
**甚至自动生成了定格动画偶人常见的底座转盘** —— 模型确实理解 stop-motion 这个语义。

样张已存入仓库：`assets/character/agnes-felt-test-frame.png`

### 一条对架构有影响的发现

Agnes 图片输出的 URL 是**公网可直接访问**的。
→ 在「Agnes 出图 → Agnes 出视频」这条纯 Agnes 链路上，**测试阶段不需要 R2 中转**，
  可以把图片 URL 直接当 `first_frame` 传给视频接口。

⚠️ 但 R2 **仍然必须保留**，原因有三：
1. CapCut/Seedream 和本地图片没有公网 URL，必须自己托管
2. Agnes 的输出 URL **可能过期**（`expires_at` 字段存在），而 IP 资产需要长期留存
3. 官方明确要求媒体 URL 在任务完成前持续有效

## 4. 🚨 视频链路：免费队列持续饱和 —— 这是最重要的运营发现

```
HTTP 503
{"code":"video_queue_full","message":"video queue is full, please retry later"}
```

**实测持续时间：20 分钟以上，19 次尝试，无一次成功。**

| 测试维度 | 结果 |
|---|---|
| `mode: keyframe` | 全部 `video_queue_full` |
| `mode: text` | 全部 `video_queue_full` |
| → 结论 | **饱和是模型级的，与模式无关** |
| `agnes-video-v2.0` 备选 | `fail_to_fetch_task`，不能当退路 |

### 这条发现改变了生产模型

原先的隐含假设是「想生成就能生成」。**实际是：免费视频是抢占式资源，不是按需资源。**

| 影响 | 说明 |
|---|---|
| 不能同步等 | 「点一下等 3 分钟出片」的交互不成立 |
| 必须长时间挂机抢 | 退避重试的时间尺度是**分钟到小时**，不是秒 |
| 两阶段抽卡引擎被验证 | 拿到队列位就立刻落盘 `video_id`，是完全正确的设计 |
| 9 账户是否有用**未知** | 队列可能是全平台共享的。**需要 Owner 用 2 条以上 Key 同时测才能确认** |

### ❓ 留给 Owner 的关键测试

> **用两条不同账户的 Key，在同一时刻各发一个视频请求。**
> - 如果两条都 `video_queue_full` → 队列是**全平台共享**的，9 个账户对视频**没有帮助**（对图片/文本仍然有用）
> - 如果有一条成功 → 队列是**按账户**的，9 账户抽卡策略成立，价值巨大
>
> 这个答案直接决定 AniFlow 的产能模型，是目前最高价值的一次测试。

## 5. 代码侧的对应修改（本轮已完成）

| 修改 | 原因 |
|---|---|
| **限流器改为每 Key 独立** | 原本 9 个账户共用一个全局 16 req/min 限流器，**浪费 8/9 的产能**。限流是按账户算的 |
| 新增 `is_queue_full()` 识别 | 503 + `video_queue_full` 是**可重试且未计费**的，必须与「真失败」区分开 |
| 队列满专用长退避 | 默认 45s × 尝试次数，上限 120s；普通网络抖动仍用 8s 短退避 |
| 失败原因区分标注 | 记为 `queue_full` 而非泛泛的 create failed，避免误以为是 prompt 写坏了 |
| 创建重试次数 3 → 6 | 匹配真实饱和时长 |

测试：抽卡引擎 **25 个通过**，全量 **70 个通过**（仍为离线 mock）。

## 6. TTS 选型更新（基于 Owner 提供的信息）

Owner 有 Vertex AI 额度。调研结论：

| 方案 | 优势 | 风险 |
|---|---|---|
| **Gemini 3.1 Flash TTS** `gemini-3.1-flash-tts-preview` | 30 音色、70+ 语言、**200+ 音频标签**、**自然语言导演式控制**（可直接写「用困惑的语气慢慢说」）、**原生双说话人** | **Preview 状态无 SLA**；有资料称免费额度**不可商用** |
| **CosyVoice 2**（自托管） | Apache 2.0 **商用无忧**、中文自然度 MOS 4.7 最高、工程成熟 | 需要自己部署，要 GPU |
| **IndexTTS2** | **精确时长控制**（镜头固定 4–12 秒，配音必须卡准） | 同样需自部署 |

### 建议

> **主选 Gemini 3.1 Flash TTS**，理由是它的**双说话人**能力正好对上
> 「雪所长 + 第二角色」的相声式结构，而导演式风格控制正好服务喜剧节奏。
> 这两点是 CosyVoice 给不了的。
>
> **但商业化前必须切到 Vertex AI 付费档**，不要用免费额度做商用内容（授权风险）。
> 成本极低：一集 60–90 秒约 $0.01–0.05。
>
> **CosyVoice 2 作为备胎保留**，Apache 2.0 是干净的商用退路，防 Preview 变更。
