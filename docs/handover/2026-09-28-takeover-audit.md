## 3. 商业方向审计

### 3.1 值得继续吗？——值得，但不是按现在的设定

先说不白吃的真实数据（创始人朱宇辰访谈一手）：
- 2019年7月入场，**一周做 50 集**，两个月 100 万粉
- 单条视频带货 **600 万元**；单月直播 **超 1000 万元**
- 一年 **46 万份订单**，抖音 GMV 千万级
- 延伸：图书（话山海经系列）、杂志（**月征订 30 万册**）

### 3.2 但真正的成功密码被误读了

项目现在学的是「固定角色 + 搞笑剧情 + 一集一知识点」。
**这是表层。** 创始人自己说的深层原因是：

> 「跟美食相关的内容在**招商时就要比别的内容好招一些**」
> 「这样就能顺理成章地**链接到『食品』这个很大的消费市场**」

也就是说，**不白吃先选定了消费品类，再设计的 IP** —— 不是先做 IP 再找变现。

> 🚨 **这是当前 AniFlow 最大的战略缺陷：「搞笑科普」是一个没有消费落点的泛品类。**
>
> 泛科普的广告主是谁？知识付费？课程？这些都不匹配一只猫。
> 流量可能做得起来，但**流量到钱这一段是断的**。

创始人还点破了天花板：「不可能每条视频都带货，这会让粉丝很反感」——
所以他们才去做虚拟人直播、图书、杂志。**单靠视频广告是养不活一个动画 IP 的。**

### 3.3 2026 年的新变量：监管已经反转了「量产」的价值

这是提示词里完全没有的、但**足以改变技术路线**的信息：

| 新规 / 动作 | 生效 | 对 AniFlow 的直接影响 |
|---|---|---|
| 《AI生成合成内容标识办法》全面落地 | 2026-04-01 | AI 内容**必须显式标注**，未标注 → 限流/下架/封号 |
| 抖音 AI 短剧审片标准 | 2026-05 | AI 占比≥50% 须在**片头前3秒+封面+简介**三处标注 |
| 抖音专项治理 | 2026-04起 | **下架超 7 万部**；日上新 2000+ → 350；**过审率仅 30%** |
| 抖音明令禁止 | — | **机械配音、音画不同步、人物穿模、静态PPT式敷衍** |
| 小红书 | 2026-01 | 推荐 **AI+真人混合，≥50% 真人** |
| 微信公众平台 | 2026 | 禁止**脚本/程序托管方式批量连续发布**、禁止脱离真人参与的发布流程 |

**三个必须立刻内化的结论：**

1. **「低人工、高自动化、日更矩阵」在 2026 年是高风险策略。** 平台正在精准打击它。
2. **配音质量是合规红线，不是加分项。** 「禁止机械配音」直接写进了抖音审片标准 —— 而 AniFlow 目前**完全没有配音模块**。
3. **合规反而有红利。** 多方资料指出：当大量低质 AI 内容被限流时，主动合规的内容获得「稀有性溢价」和推荐加权。

### 3.4 修正后的商业判断

| 问题 | 我的结论 |
|---|---|
| 2026 还有机会吗 | **有**，但窗口从「产能红利」变成了「合规 + 质量 + IP 红利」 |
| 相比真人科普的优势 | 角色不会跑、不会塌房、可无限复用、边际成本趋零（投资人原话：真人有不确定因素，动画 IP 牢牢在公司手里） |
| 内容能规模化吗 | 技术上能。**但不应该规模化到日更** —— 监管和算法都在惩罚它 |
| 同质化风险 | **极高**。科普 + AI 动画是 2026 最卷的赛道之一，「AI脸、AI腔」已引发观众抵触 |
| AI 动画质量够吗 | **图片够了，视频勉强够**。720P 上限是真实约束，但竖屏短视频场景可接受 |
| 中外双市场 | **不要同时做**。V0.1 只做中文。但脚本结构要为 i18n 预留（见 5.3） |
| 最现实的盈利路径 | ① 品牌广告植入（《今天研究啥》天然容器）→ ② 宠物/家居消费品带货 → ③ 图书/内容授权。**不要指望平台分成** |
| 何时开始商业化 | 不白吃是**推出 3 个月**就开始视频带货。不要等到 10 万粉。**但前提是先有能看的内容** |

### 3.5 最可能的失败原因（按概率排序）

1. **有流量没收入** —— 泛科普无消费落点（最可能，且当前方案正朝这个方向走）
2. **平台合规问题限流** —— 未做 AI 标识、机械配音被判低质
3. **观众对「AI 腔」的抵触** —— 内容能生成但没人看完
4. **角色一致性不稳定** —— IP 无法被记住，等于没有 IP
5. **一个人 + 全自动的幻想** —— 自动化产出平庸内容，平庸内容拿不到流量

## 4. IP 方向审计

### 4.1 保留的部分（判断：正确）

`雪所长` / `不懂研究所` / `喵有此理` / `猫不瞎说` / `今天研究啥` / `懂个喵` / `因为不懂，所以研究` / `别说，竟然喵有此理！`

这套体系**结构完整度超出预期**：母IP、主角、世界观、旗舰栏目、事实栏目、商业容器、meme、理念、固定口号 —— 该有的都有，且口号有记忆点。**不需要推翻。**

### 4.2 猫作为主角：是资产，不是限制 —— 但「研究所」解决不了品类问题

「猫会不会限制科普品类」是个真问题，但**「研究所」这个抽象世界观解决不了它**。
抽象空间 = 什么都能讲 = 什么都不精 = 招商时说不清自己是什么号。

> 💡 **我的建议：把「不懂研究所」明确设定在「人类的家」里。**
>
> 一只猫，趁主人不在，在家里偷偷开了个研究所，研究人类家里那些它看不懂的东西。

这一个改动同时解决四个问题：

| 问题 | 怎么解决的 |
|---|---|
| 消费落点缺失 | 「家里的东西」= 食品、家电、日用、清洁、数码、宠物用品 —— **全是消费品类** |
| 猫限制品类 | 猫对人类世界天然「不懂」，好奇是合理的，不需要解释 |
| 广告怎么自然进入 | **任何商品进家门 = 新研究对象**。《今天研究啥》天然就是广告容器，不违和 |
| 喜剧从哪来 | 「猫的视角看人类世界」本身就是**陌生化喜剧引擎**，不依赖段子手 |

而且它**不锁死宠物品类**：猫粮、猫砂是「家里的东西」的子集，未来随时能接，但账号不会被打成宠物号。

### 4.3 需要第二角色 —— 而且它应该长在事实防火墙上

**必须加。** 单角色独白撑不起长期喜剧，且「不懂」的人设无法自己输出正确知识。

**不建议**人类科学家：会抢戏、削弱猫的主体性、且「人给猫讲课」的姿态不讨喜。

**建议**：一个**不会说谎的家用智能设备**（智能音箱 / 老式仪器拟人化）。

喜剧引擎：

```
雪所长凭直觉乱猜  →  荒谬但好笑（观众代入）
第二角色给出事实  →  正确但扫兴（知识落地）
雪所长强行狡辩    →  「别说，竟然喵有此理！」
```

**技术上的额外好处**：`Fact Pack` 里的 `LOCKED_FACTS` / `SOURCE_A` / `SOURCE_B` 终于有了**剧情内的出口** ——
由第二角色念出来，既是事实防火墙，又是笑点节奏器。栏目《猫不瞎说》天然归它主持。
**事实校验从「制度约束」变成了「角色设定」，这是结构性的优雅。**

### 4.4 一个需要你知道的商业摩擦点（我不强改）

`雪所长不懂` 里的「不懂」，在**招商时会略微减分** —— 品牌方潜意识不愿意让「不懂的人」给产品背书。

不白吃的「不白吃」是自嘲但暗含「懂吃」；「不懂」则是纯粹的否定。

缓解方式（不必改名）：**对外强调「所长」和「研究所」的权威感，「不懂」只作为起点**。
理念「因为不懂，所以研究」已经处理了这个问题 —— 研究完就是懂了。**建议保留现名，但在 IP 手册里明确这条话术纪律。**

### 4.5 10–20 年可持续性

成立。动画 IP 不会老、不会塌房、不流动。
唯一前提：**角色视觉必须能被稳定复现** —— 这从 IP 问题变成了技术问题（见 6.2）。

关于是否围绕真实雪雪建立外观：**建议「像但不等于」**。取其花色与神态特征做识别符，但比例卡通化。
理由：真实猫的写实比例在 AI 生成中一致性更差，且卡通化更利于周边衍生。

## 5. 内容方向审计

### 5.1 搞笑科普：方向正确，但需要加「场域约束」

不加约束的泛科普 = 选题无边界 = 无法沉淀人设 = 无法招商。
加上「家」之后，选题有了天然边界，而边界恰好覆盖最大的消费市场。

### 5.2 跨语言知识差：有价值，但**不是护城河**

诚实评估：

- ✅ 作为**选题来源**很有效，能持续供给「意外感」
- ❌ 作为**战略/壁垒**不成立 —— 没有任何门槛，任何人都能做，且极易被判定为搬运
- ⚠️ 真实风险：直译海外内容 = 文化语境不匹配 = 不好笑

**正确用法**：把它降级为「选题雷达」的**一个输入源**，而不是项目支柱。
且必须有**本地化改写**环节：只取事实内核，喜剧外壳完全重写。

**选题雷达什么时候开发？** —— 不是现在。等有了 20–30 条成片、知道什么选题跑得动之后再建。
现在建雷达是在优化一个还不存在的流程。

### 5.3 中英双线：V0.1 明确不做，但要留结构

同时做双市场会稀释唯一的资源（你的时间）。

**但技术上必须现在就分层**，否则以后重构代价极高：

```
事实层 (Fact Pack)     ← 语言无关，可复用
剧本层 (台词/笑点)      ← 语言相关，需重写而非翻译
画面层 (分镜/关键帧)    ← 语言无关，可复用
配音层 (TTS)           ← 语言相关
字幕层                 ← 语言相关
```

这样未来做英文版是**替换两层**，不是重做。Easy English 衍生同理，**现在不做**。

## 6. 技术审计

### 6.1 模型层：三个全部要换，且换完全免费

详细契约见 **`docs/model-contracts.md`**（本轮新建，已核实到官方文档）。

| 角色 | 现用 | 应改为 | 理由 |
|---|---|---|---|
| 文本/编剧/QA | `agnes-2.5-flash` | **`agnes-3.0-flash`** | 同样免费，更强更快（235 vs 159.5 tok/s），生产 API 上下文 1M |
| 图片 | `agnes-image-2.1-flash` | **`agnes-image-2.5-flash`** | 官方明示「参数完全相同、质量全面超越」——**零成本换字符串** |
| 视频 | `agnes-video-2.5-flash` | **保持** | 已是正确选择，且 $0/秒 |

**全链路 API 成本 = $0。** 唯一会花钱的是 `agnes-video-2.5`（非 Flash，$0.025/秒），**不要默认启用**。

### 6.2 四个改变架构的技术发现

#### 发现 A：`agnes-video-v2.0` 已经下架了

官方文档索引和 Pricing 页**都没有这个模型**。
→ 前端里整套 V2.0 参数契约（`num_frames`、`frame_rate`、inference steps、negative prompt、分辨率档位）**全是死代码**。
→ AGENTS.md 里「必须保留 V2.0 参数契约」这条规则**已失效，应删除**。

#### 发现 B：`keyframe` 和 `reference` 模式互斥

官方契约明确：`keyframe` 模式禁止传 `images`；`reference` 模式禁止传 `first_frame`/`last_frame`。

> **这意味着：不能既锁定首尾帧、又同时喂角色参考图。**
> → 角色一致性**必须在上游图片阶段解决**，靠 `agnes-image-2.5-flash` 的多图合成从 Identity Anchor 出帧。
> → 视频阶段用 `keyframe` 继承一致性。
> → 现有的 Character Bible / Identity Anchor 设计**因此被证明是对的，必须保留**。

#### 发现 C：`A → B → C` 两段 5 秒的硬结构没有必要了

`agnes-video-2.5-flash` 支持 **4–12 秒**（后端 config 其实已允许 4–12，是上层流程写死了 3 帧 2 段）。

比较结果：

| 方案 | 评价 |
|---|---|
| 旧：3 帧 / 2 段 / 各 5 秒 / 拼接 | ❌ 人为制造接缝，还要为接缝做 QA |
| 单段 8–12 秒首尾帧 | ✅ **无接缝**，但中间过程不可控 |
| reference 模式单段 | ⚠️ 一致性交给模型，不可控，作备选 |
| **可变 shot-list（推荐）** | ✅ 一集 = N 个镜头，**每镜头 4–12 秒自适应**，镜头切换是**创作意图**而非技术妥协 |

→ 60–90 秒的科普短片本来就需要多镜头。拼接不会消失，
但「**恰好 3 帧、恰好 2 段、恰好 5 秒**」这个僵硬约束应该删除，改为**镜头数与时长由剧本决定**。
→ 「接缝 QA（49%/51% 采样）」的重要性大幅下降 —— 有意的镜头切换不需要无缝。

#### 发现 D 🚨：Agnes 完全没有 TTS，而项目也完全没有配音模块

Agnes 文档索引只有 Text / Image / Video **三类，没有任何语音模型**。
代码里 `grep` 全仓库：**零 TTS、零字幕、零音频处理**。

**这是整个项目最严重的缺口，而旧方案从未提及它。**

对「搞笑科普」来说，**台词就是内容本体**。没有配音 = 没有产品。
且抖音审片标准**明令禁止「机械配音」** —— 配音质量直接决定能否过审。

**TTS 选型结论**（2026 开源横评）：

| 候选 | 许可 | 优势 | 判断 |
|---|---|---|---|
| **CosyVoice 2** | Apache 2.0 | 中文自然度 MOS 4.7 最高，工程最成熟（Docker/vLLM/gRPC） | ✅ **基线首选** |
| **IndexTTS2** | Apache 2.0 | **精确时长控制** + 12 种情感解耦 | ✅ **升级项**：视频段时长固定，配音必须卡准 |
| Fish Speech S2 | ⚠️ 商用需单独授权 | 表现力强 | ❌ 商用风险，排除 |

**建议：CosyVoice 2 打底跑通，再用 IndexTTS2 做「时长锁定配音」升级。两者都是 Apache 2.0，商用安全。**

### 6.3 CapCut / Seedream：建议**砍掉**

这是本次审计中最明确的一个「删除」建议。理由：

1. **前提已失效** —— 当初选 Seedream 是因为觉得它参考图更好。但 `agnes-image-2.5-flash` 官方明示「全面超越 2.1」，且原生支持**多图合成**、免费、API 直连。
2. **架构上不再需要** —— 发现 B 说明一致性必须在图片层解决，而 2.5 的多图合成正是为此设计的。
3. **永久维护负债** —— 依赖登录态、UI 选择器、页面改版、反自动化策略。每次 CapCut 改版就会坏。
4. **合规与授权风险** —— 浏览器自动化 + 第三方平台产出物的商用授权链条不清晰，对一个要商业化的 IP 是隐患。
5. **从未验证过一次真实产出** —— 沉没成本是代码，不是成果。

**不是「先不做」，是建议删除**：`src/aniflow/capcut/`、`scripts/capcut_agent_probe.py`、相关前端面板与 AGENTS 规则。
（决定权在你。若你坚持保留，我会降级为 experimental 插件并明确不保证可用。）

### 6.4 强制要求六：每模型独立配置 —— 现状与实证

**已发现一个真实的不兼容案例，证明这条要求完全必要：**

| | `agnes-image-2.0-flash` | `agnes-image-2.5-flash` |
|---|---|---|
| `size` 语义 | 像素串 `1024x768` | **档位** `2K` |
| `ratio` | 无此参数 | 独立参数 |

**把 2.0 的 size 塞给 2.5 会得到错误画幅。**
视频侧同理：`text`/`keyframe`/`reference` 三模式各有**互斥禁用字段**，传错直接 HTTP 400。

现状评估：后端 `config.py` 是扁平全局配置（`agnes_image_model` 一个字符串走天下），**不满足要求**。
前端做到了双视频模型独立存储（这部分设计是对的，值得保留并推广）。

→ 需要引入 **per-model schema registry**：每模型自带参数表、默认值、上下限、可用模式、独立记忆。这是下一阶段的核心改造项之一。
